# AnkiTTS — озвучка колод Anki голосами GPT-SoVITS

> Полное описание устройства проекта, всех функций и история исправлений —
> в `PROJECT.md`. Здесь — практическая инструкция по использованию.

Автономный инструмент: **код живёт в любой папке** (можно скачать с GitHub и
распаковать куда угодно), а **движок GPT-SoVITS стоит отдельно** — где он уже
установлен. Если у тебя есть GPT-SoVITS и Anki с AnkiConnect — указываешь папку
движка и всё работает.

## Что нужно, чтобы заработало

1. **GPT-SoVITS** установлен и запускался (со своим `runtime\python.exe` и `api_v2.py`).
2. **Anki** запущен с включённым **AnkiConnect** (http://127.0.0.1:8765).
3. Этот инструмент распакован в любую папку.

## Куда смотрит инструмент за папкой движка

Папка GPT-SoVITS резолвится в порядке приоритета (первый найденный берётся):

1. переменная окружения `GPT_SOVITS_ROOT`
2. файл `gptsovits_path.txt` рядом с программой (одна строка — путь); его
   удобно создать один раз или он пишется автоматически из `AnkiTTS.exe`
3. `%APPDATA%\AnkiTTS\config.json` → `"gptsovits_path"` (его пишет `AnkiTTS.exe`)
4. сама папка инструмента (если положить его внутрь GPT-SoVITS — старое поведение)

В папке движка должны быть `runtime\python.exe` и `api_v2.py`.

## Две точки входа

### 1. `AnkiTTS.exe` — программа с интерфейсом (двойной клик)

Тонкая оболочка: сама находит/запоминает папку движка, читает голоса из
`voices.json` и колоды из AnkiConnect. Вся работа (синтез, хирагана, веса,
запись в Anki) выполняется запуском `voice_pipeline.py` тем интерпретатором,
который стоит в папке движка. Поэтому exe лёгкий и не тащит torch.

* Первый запуск: укажи папку GPT-SoVITS (обычно она находится сама на диске).
* Дальше путь запоминается (`%APPDATA%\AnkiTTS\config.json` + `gptsovits_path.txt`).
* В окне **три вкладки** (современный плоский дизайн: по умолчанию **тёмная
  тема** — переключается кнопкой в шапке («Светлая тема» / «Тёмная тема»),
  выбор сохраняется в `%APPDATA%\AnkiTTS\config.json`; статусы-чипы в шапке
  — Anki / Сервер / число голосов, тёмный лог-терминал;
  у каждого параметра есть приписка, в какую сторону его крутить):
  * **«Голос»** — список голосов (красивые имена + индикация «файлы на месте»)
    и редактор голоса как в webui GPT-SoVITS: референс (+прослушивание), текст
    и язык промпта, вспомогательные референсы, чекбокс «без текста референса»,
    слайдеры `temperature` / `top_p` / `top_k` / `speed` / `seed`. Кнопки
    «Прослушать тест» (сохраняет и синтезирует пробу), «Сохранить» (пишет в
    `voices.json`), «Голоса в движке» (ищет веса, см. ниже) и «voices.json»;
  * **«Anki»** — колода (со счётчиком заметок), выбор полей карточки
    (откуда брать текст предложения/слова и куда писать звук), режим,
    лимит, «переозвучить всё»;
  * **«Финализация»** — «Начать озвучку», «Стоп», «Проверить колоду»,
    «Самопроверка» и лог хода работы прямо в окне.

Диагностика без интерфейса (для отладки):

```
AnkiTTS.exe doctor
```

Если exe не запускается или ругается Windows Defender — это типовая реакция
на PyInstaller-сборку: добавь в исключения Defender или пересобери (см. ниже).

### 2. `pipeline.bat` — меню в консоли (та же логика, без exe)

Сам находит движок (см. приоритет выше) и запускает пайплайн. Без аргументов
открывает интерактивное меню, с аргументами работает как команда.

| Файл | Что это |

| `anki_tts.py` | Старый одноразовый скрипт (оставлен для истории, пайплайн его не использует) |

## Стандартный цикл

```
1. Список голосов        pipeline.bat list
2. Проверка окружения    pipeline.bat selftest
3. Новый голос           pipeline.bat add --name sakura --gpt ... --sovits ... --ref ... --prompt-text "..."
4. Тест голоса           pipeline.bat test --voice sakura --text "こんにちは"
5. Новая колода          pipeline.bat make-deck --voice sakura --query "deck:Архитектура" --limit 20
6. Проверка              pipeline.bat check --deck "Сакура"
```

### Поля карточек

У разных колод поля называются по-разному — поэтому откуда брать текст и куда
писать звук настраивается (в GUI — вкладка «Anki», в консоли — флаги):

```
--sentence-src "Sentence"       поле с текстом предложения
--sentence-audio "SentenceAudio" поле, куда кладётся звук предложения
--word-src "Expression"         поле со словом (для Expression работает разбор фуриганы)
--word-audio "ExpressionAudio"  поле, куда кладётся звук слова
```

Флаги есть у команд `voice`, `make-deck` и `check` (`check` нужны только
аудио-поля). Дефолты — старые значения, старые вызовы работают как раньше.

### Характер речи (sampling)

`temperature` / `top_p` / `top_k` хранятся **на голос** в `voices.json`
(вкладка «Голос», слайдеры) и уходят в API при каждом синтезе. Дефолты
взяты из официального webui GPT-SoVITS (0.6 / 0.6 / 20) — спокойнее, чем
«горячие» дефолты чистого API (1.0 / 1.0 / 15), которые звучат излишне
эмоционально. Чем меньше `temperature`/`top_p` — тем ровнее речь.

### Поиск голосов в движке

В папке движка обычно копится много весов: разные голоса, версии (v2Pro /
v2ProPlus), эпохи (`-e5` … `-e50`). Их не нужно вносить руками:

* **в GUI** — кнопка «Голоса в движке» (вкладка «Голос») плюс **автоскан при
  старте программы**: обходятся папки `GPT_weights*` и `SoVITS_weights*`,
  для каждого голоса берётся самая свежая пара GPT+SoVITS, и новые голоса
  дописываются в `voices.json` (уже записанные не перезаписываются);
* **в консоли** — `pipeline.bat scan` (показать, что найдено) и
  `pipeline.bat scan --apply` (дописать новые голоса в `voices.json`).

Правила сопоставления: GPT-ckpt парится с SoVITS-pth по имени голоса **внутри
одной версии** (v2Pro никогда не смешивается с v2ProPlus — они несовместимы);
из эпох берётся самая свежая. У вновь найденного голоса обычно ещё нет
референса — в списке он отмечен ✗, и референс (3–10 с) с текстом промпта
нужно выбрать вкладкой «Голос».

## Как работает преобразование в хирагану

GPT-SoVITS для японского разбирает текст морфологом **MeCab** (в составе
pyopenjtalk). У MeCab есть две особенности, из-за которых «сырой» текст
карточки отдавать напрямую нельзя:

* **Катакану он переделывает.** Слово, набранное катаканой, MeCab
  токенизирует по собственным словарям и часто выдаёт искажённое чтение
  (например, `IEC` → アイエースィー вместо правильного アイエーシー).
  **Хирагану он оставляет нетронутой.**
* **Иероглифы читает не всегда верно** — особенно редкие и узкоспециальные
  (архитектурные термины вроде 合折釈). Для таких слов есть словарь замен.

Поэтому каждый текст проходит конвейер `kanaize()` — шаги строго в этом
порядке:

1. **NFKC-нормализация** (`unicodedata.normalize`). Сводит к обычным формам:
   полноразмерную латиницу и цифры (`ＩＥＣ１２３` → `IEC123`), полукатакану
   с дакутеном (`ｶﾞ` → ガ) и разложенные знаки (`か` + ゙ → ガ). Без этого
   MeCab встречает символы, которые не умеет разбивать, и ломает разбор
   **всего предложения**, а не одного слова.
2. **Словарь `kana_overrides.txt`** — только слова, которые MeCab читает
   неверно (`合折釈` → あいおれくぎ). Длинные ключи применяются раньше
   коротких. Чем меньше словарь — тем стабильнее чтение соседних слов:
   лишняя замена меняет контекст морфологического разбора.
3. **Латиница → катакана по буквам** (`IEC` → アイエーシー) — для остатков
   латиницы, не попавших в словарь.
4. **Катакана → хирагана** (`アイ` → あい). Отдельно обработаны редкие
   знаки вне основного диапазона — ヷ ヸ ヹ ヺ (уточнённые «ва/ви/ву/ве»)
   и повторяющиеся ヽ ヾ, иначе они бы остались катаканой и попали в MeCab.
5. **g2p (pyopenjtalk/MeCab)** — запускается **только если в тексте остались
   иероглифы**; превращает их в чтение (катаканой).
6. **Повторный проход «катакана → хирагана»** — результат g2p местами снова
   катакана. На выходе в API уходит текст целиком в хирагане.

Что конвейер **не трогает**: саму заметку в Anki (обрабатывается только
копия текста, которая уходит в синтез) и фуригану/поле `ExpressionReading` —
чтение слова берётся оттуда как есть.

Проверка ковертера встроена: `pipeline.bat selftest` прогоняет батарею
сложных слов (полукатакана, полноразмерная латиница, ヴ-серия, словарные
замены, длинные глагольные формы) и сверяет ожидаемый результат.
Расширенная батарея (58 сложных слов из колоды «Архитектура», допускаются
оба безвредных варианта нотации): `runtime\python.exe kana_stress.py`.

## Подстановка чтения из карточки в предложение

Даже с конвейером хираганы MeCab местами читает редкие специальные слова
неверно — а в карточке уже лежит **проверенное чтение**. API GPT-SoVITS
принимает только текст (канала «готовое чтение» у него нет), поэтому
инструмент подставляет чтение прямо в текст перед синтезом: MeCab видит
хирагану и не может ошибиться.

Источники чтения (по порядку):

1. **`SentenceFurigana`** — если поле заполнено и совпадает с предложением,
   читается весь текст разом (чинит все слова сразу). В колоде «Архитектура»
   поле пустое, поэтому работает второй пункт.
2. **`ExpressionFurigana` / `ExpressionReading`** — берётся чтение слова из
   `Expression` и подставляется в предложение вместо этого слова.

Как разбирается фуригана `相欠[あいが]き継[つ]ぎ`:

* пары «основа → чтение» разбираются по скобкам;
* чтение в скобках покрывает основу целиком, **кроме кана-окуриганы**
  (ки в `き継[つ]` — своя, её оставляем), а **латиницу не оставляем** —
  её звучание уже есть в начале чтения, иначе задвоится
  (`IEC規格[アイイーシーきаку]` → `アイイーシーきаку`, а не `IEC`+ещё раз);
* на выходе — полная пара: слово `相欠き継ぎ` → чтение `あいがきつぎ`.

Подстановка делается **только безопасно**:

* только если слово целиком найдено в предложении;
* только если чтение — чистая кана (иероглифы в «чтении» = это не чтение);
* разметка фуриганы обязана совпасть со словом из `Expression` — иначе
  подстановка пропускается, предложение остаётся как есть.

Что это даёт (проверено на реальных карточках колоды «Архитектура»):

| Слово | Без подстановки | С подстановкой |
|---|---|---|
| I形梁 (`I形[アイがた]梁`) | あいがた**は**り | あいがた**ば**り (как в карточке) |
| アイススケート場 (`…場[じょう]`) | あいすすけーと**ば** | あいすすけーと**じょう** |
| 相の間 (`相[あい]の間[ま]`) | あいのま**い** | あいの**ま** |
| 相欠き継ぎ | ломало предложение | あいがきつぎ |

Слова без иероглифов (чистая латиница `IEC`, `IIW`) подстановки не
получают — их и так правильно читает шаг «латиница → катакана».

### Режим источника чтения (настройка)

Источник подстановки можно переключить — в программе (вкладка «Anki»,
строка **«Чтение слова ← источник»**) или ключом `--reading` в консоли:

| Режим | Что делает |
|---|---|
| **Авто** (по умолчанию) | как описано выше: `SentenceFurigana` → `ExpressionFurigana`/`ExpressionReading` |
| **Не подставлять** (`--reading off`) | фуригана игнорируется полностью: предложение читает MeCab само, слово озвучивается по написанию без разметки |
| **Имя поля** (`--reading Кана`) | чтение слова берётся **строго из указанного поля** — для слов с нестандартным чтением, которое известно заранее; в списке GUI поля колоды показываются как варианты |

Поведение в режиме «Имя поля»:

* в предложение подставляется чтение из этого поля (теми же безопасными
  правилами: только чистая кана, только если слово найдено в предложении);
* если поле пустое — подстановки нет (авто-фуригана **не** подхватывается —
  вы явно указали источник);
* озвучка слова берёт чтение из поля; если поле пустое — фолбэк на
  фуригану `Expression` (лучше так, чем читать MeCab'ом наугад).

## Что делает автоматически

* поднимает API-сервер GPT-SoVITS, если он не запущен, и дожидается готовности;
* переключает веса голоса на лету (`/set_gpt_weights` + `/set_sovits_weights`);
  при нехватке памяти — перезапуск сервера и повтор;
* переводит текст карточек в хирагану (NFKC → словарь замен → латиница
  катаканой → **катакана в хирагану** → MeCab для оставшихся иероглифов →
  снова хирагана; подробно — раздел «Как работает преобразование в хирагану»);
* чтение слова берётся из `ExpressionReading` / фуриганы (для поля `Expression`,
  для любого другого поля — просто его текст);
* клонирует карточки из исходной колоды (аудио-поля очищаются, ставится тег голоса);
* синтезирует слово и предложение, кладёт ogg в медиа Anki, пишет `[sound:...]`;
* пропускает уже озвученное (без `--force`);
* проверяет результат: поля заполнены и файлы реально есть в медиа.

## Важные ограничения (проверено на практике)

* **Референс 3–10 секунд** — API отклоняет всё вне этого диапазона. `list` и
  `selftest` показывают длительность и флаг, если она неверна.
* **Длинный aux-референс** → CUDA OOM на видеокарте 6 ГБ. aux держать коротким или не задавать.
* **Словарь замен не раздувать.** Лишняя замена хираганой меняет контекст
  морфологического разбора и ломает чтение соседних слов. В `kana_overrides.txt` —
  только слова, где MeCab действительно даёт неверное чтение.
* **Катакана не должна попадать в MeCab** — он переделывает её, а хирагану
  оставляет нетронутой. Поэтому `kanaize` превращает катакану в хирагану до g2p.
* Заметка, открытая в редакторе Anki, не принимает запись — пайплайн печатает
  подсказку «закрой карточку в редакторе» и идёт дальше.
* **Не используй `localhost` в URL к AnkiConnect** — резолв IPv6 даёт ~2 с задержки
  на каждый запрос. В коде адрес `http://127.0.0.1:8765` (заголовок
  `Origin: http://localhost` остаётся).

## Пересборка exe

Изменения в `anki_gui.py` в готовый exe не попадают — нужна пересборка
(~20 секунд). PyInstaller ставится в интерпретатор движка:

```
set ENGINE=C:\Путь\К\GPT-SoVITS
%ENGINE%\runtime\python.exe -m pip install pyinstaller
%ENGINE%\runtime\python.exe -m PyInstaller --noconfirm --onefile --windowed ^
    --name AnkiTTS --distpath . --workpath %TEMP%\pyi_build --specpath %TEMP% anki_gui.py
```

Важно: пересборка НЕ трогает `voice_pipeline.py` — его правки подхватываются
сразу, без пересборки exe. Пересборка нужна только для правок интерфейса.

Отладочная консольная версия (видно traceback):

```
%ENGINE%\runtime\python.exe -m PyInstaller --noconfirm --onefile --console --name AnkiTTS_dbg anki_gui.py
AnkiTTS_dbg.exe doctor
```

## Типовые ошибки

| Сообщение | Что делать |
|---|---|
| `Не найдена папка GPT-SoVITS` | Указать путь: `gptsovits_path.txt`, env `GPT_SOVITS_ROOT` или через `AnkiTTS.exe` |
| `AnkiConnect недоступен` | Открыть Anki |
| `Референс X с — API требует 3–10 с` | Перерезать клип |
| `Не получилось переключить... Перезапуск` | Норма, пайплайн сам перезапустит сервер и повторит |
| `Веса не загрузились` | Проверить пути в `voices.json` (относительные — от папки движка) |
| `Колода уже содержит N карточек` | Дозвать `voice`, либо `--force` для нового набора |
| `закой карточку в редакторе Anki` | Закрыть редактор в Anki |
| `сервер вернал пустой звук` | Обычно видеопамять занята чужими процессами (другая программа на GPU). Закрыть их или перезапустить сервер: `pipeline.bat serve --voice <голос>` |
| `Не хватает видеопамяти — перезапускаю сервер` | Норма: пайплайн сам перезапускает GPT-SoVITS и повторяет запрос. Если повторяет часто — закрыть чужие программы на GPU |


## Работа на других компьютерах (портативность)

Проверено и учтено в коде:

* **Windows 10/11**; GPU с CUDA (комфортно — от 6 ГБ видеопамяти); движку при
  старте нужно **~4–6 ГБ свободной оперативной памяти** — если сервер не
  поднимается, закрой тяжёлые программы и повтори.
* Папка инструмента может лежать **где угодно** — в том числе с кириллицей и
  пробелами в пути.
* **Корпоративный прокси/VPN не мешает**: все локальные запросы (Anki,
  GPT-SoVITS) идут напрямую, мимо системного прокси.
* Если **порт 9880 занят чужой программой**, пайплайн сам определит, какая
  именно, и не убьёт её — попросит закрыть.
* **Два параллельных запуска** озвучки блокируются: второй сообщает, что
  первый ещё работает (файл `logs\pipeline.lock` в папке движка).
* Вся кодировка — UTF-8 (переменные `PYTHONUTF8` ставятся автоматически).
* Нужен `pyopenjtalk` в окружении движка (в стандартном GPT-SoVITS уже есть;
  если нет — пайплайн напечатает точную команду установки).
* Большие колоды обрабатываются частями; для быстрой проверки колоды без
  скачивания аудио — `check --deck ИМЯ --fast`.

## Релизы на GitHub

Во вкладке **Releases** публикуется готовый `AnkiTTS.exe` — чтобы
пользователь скачивал один файл и запускал, не собирая самому:

1. GitHub → вкладка **Releases** → **Draft a new release**
2. Тег: `v1.0`, заголовок: `AnkiTTS v1.0`
3. В **Attach binaries** приложить `AnkiTTS.exe` из этой папки
4. Описать, что новое, и опубликовать

Ссылка на файл появится в описании релиза («Assets → AnkiTTS.exe»).
