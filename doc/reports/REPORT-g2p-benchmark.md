# Отчёт: сравнение ядер G2P на корпусе ROHAN4600

Проект: AnkiVoice — локальная озвучка колод Anki голосами GPT-SoVITS  
Статус: исследование завершено, релиз не пересобирается (строгий запрет до прохождения всех этапов отчёта).

## 1. Цель и метод

Честное сравнение вариантов чтения японского текста (kanji → kana) на размеченном корпусе ROHAN4600 (4600 предложений, формат `ID:текст_с_фуриганой,КАТАКАНА_ЭТАЛОН`). Метрика KER (Character Error Rate) = левенштейновская дистанция / число символов эталона. Сравниваются и «сырые» kana, и kana после нормализации долгих гласных (убрать `ー`, убрать `у` после о/у-ряда и `и` после е/и-ряда — row-aware правило `collapse_long`, применимо symmetrically к обеим сторонам).

Важное уточнение: эталон ROHAN записывается в произносительной нотации (длинныегласные через う, частица は → ワ). Наш продуктовый конвейер kanaize deliberately оставляет кана как есть (хирагана проходит мимо g2p, чтобы GPT-SoVITS сам применил правила частиц), поэтому частичное расхождение с эталоном по частицам (は vs ワ) — особенность измерения, а не ошибка чтения.

## 2. Результаты ROHAN4600

| вариант | KER кана (сырой) | KER кана (нотация=) |
|---|---|---|
| sudachi-цепочка (ядро Haqumei) | **2.74%** | **2.90%** |
| haqumei (дефолт) | 3.97% | 0.93% |
| haqumei (рохан-опции) | 0.73% | 0.75% |
| pyoj-plus | 4.92% | 1.91% |
| pyoj+tsqyomi | 4.90% | 1.89% |

- **sudachi-цепочка** — продуктовый путь `kanaize → g2p_kana`: первый ход ядро Haqumei (`g2p_core.py`,長期 помощник, JSON-протокол), при недоступности/съезде разметки — запасная цепочка Sudachi → pyopenjtalk. Улучшился с 2.93%/3.09% (до правок) до 2.74%/2.90%.
- **haqumei (рохан-опции)** — прямоесоответствие авторской методике (0.78% в оригинале), подтверждает корректность нашего затора.
- tsqyomi при загрузке модели падает с `bad allocation` (ONNXRuntime), сам бенчмарк работает — tsqyomi не встраивается в ядро (этап «модель неоднозначности», после доменного словаря).

## 3. Что изменено (и почему метрика улучшилась)

### 3.1 `g2p_core.py` — помощник ядра Haqumei
- Для иероглифовых слов используется поле **`pron`** (произносительная, контекстная форма) вместо `read` (словарная):
  - 六百 → ロッпиャк (было ロクхиゃк), 殿 → ドно (было ТОНО), は → ワ.
- `pron` очищается от мусорных знаков тона (хвостовая апострофа в `デス'`) через `_kana_only()`; если очистка пуста — откат на `read`, а при отсутствии чтения — `h.g2k()`.
- **pron берётся только для слов с иероглифами**: кана-слова/знаки/частицы проходят как есть (иначе ломается частица を → ヲ вместо «о», и приветствия コンниЧа/コンbanハ).

### 3.2 `voice_pipeline.py` — `kanaize`
- Убрана предварительная конвертация катакана → хирагана **до** вызова `g2p_kana`. Катакана сохраняется, чтобы ядро видело контекст: ビェниャк殿 → 殿 читается ДОно (в контексте иностранного имени), а не ТОно.
- Финальный результат по-прежнему приводится к хирагене (кроме `_KEEP_KATA`: コンниЧа, コンbanハ).

### 3.3 `lab\bench_rohan.py` — метрика
- `collapse_long` переделан на row-aware правило (`_ROW_VOWEL`, `_LONG_AFTER`): トウ = トо = долгая «о», а あу не схлопывается. Старое правило завышало метрику «нотация=» для у-нотации.

## 4. kana_stress (63 доменных случаев)

**49/63** (было 48/63 на старом ядре, 46/63 — ещё раньше). Прошли additionally I形鋼/I形梁/I形グルーブ (раньше падали).  
14 падений — все доменные термины плотнично-строительной тематики: 合折釘, 合釘, 合印, 合端, 相欠ки, 相欠ки継ぎ, 相决り, 相决り継ги, 相决り矧ги, 相の間, 間の宿, 仕口, 野地板, 板矧ги. Оба движка читают их по общему словарю неправильно (например, 合印 → あいいん вместо аиじるси, 仕口 → しгучти вместоしくчти). Это уровень **доменного словаря** — закрывается этапом 3-4 (майнинг из полей Anki с train/holdout-сплитом), а не правками ядра.

## 5. Разбор худших случаев (sudachi-цепочка)

1. フィオレンティーノは羞花閉月で… — 羞花閉月 читается ハハジハナヘツки (эталон シュкаヘГэцу): литературный/редкий термин, вне словаря.
2. 紅の豚 → ベни (эталон クレнаи): стилизованное чтение названия фильма, вне словаря.
3. テャー様には → ハ вместо ニ (частица は не перечитывается по дизайну kanaize).
4. デャデュнは霧雨で… — は→ハ (дизайн), ずぼん→ズボн (утолщение согласной).

Все остальные Δ5–Δ7 — частичная notaция, редкие имена и доменные слова, не систематическая ошибка ядра.

## 6. Вердикт

- Ядро Haqumei (рохан-опции, `pron`, контекст катакана) работает корректно: 0 фолбэков на 4600 предложениях, сандхи и контекстные чтения разрешаются верно.
- Интегрированный конвейер (2.74%/2.90%) уступает прямому haqumei (0.73%/0.75%) только за счёт дизайнерского решения «кана не трогать» (частицы, знаки) — для GPT-SoVITS это корректно, фронтенд сам поставит произношение частиц.
- tsqyomi не встраивать (почти ноль влияния на pyoj-plus, модель падает при загрузке).
- Следующий этап (без пересборки релиза): **доменный словарь из полей Anki с train/holdout-сплитом** + механизм кандидатов + автопоиск неизвестных слов. Только после него — пересборка установщика и обновление релиза v1.0.
