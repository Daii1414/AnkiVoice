# AnkiVoice — проект: что это, как устроено, что сделано

Документ для разработчика и для оформления репозитория. Пользовательская
инструкция — в `README.md`.

**Суть в одном абзаце:** автономный инструмент, который озвучивает карточки
Anki японскими голосами GPT-SoVITS. Код живёт в любой папке и не зависит от
места установки движка; всю «тяжёлую» работу (синтез, веса, torch) делает
уже установленный GPT-SoVITS. Главная инженерная задача проекта —
**правильно превратить текст карточки в хирагану**, чтобы MeCab не путал
редкие специальные термины, и **вставить в предложение проверенное чтение
слова прямо из карточки**.

---

## 1. Что нужно для работы (данные и требования)

| Что | Зачем | Где берётся |
|---|---|---|
| GPT-SoVITS с `runtime\python.exe` и `api_v2.py` | синтез речи | установлен отдельно; путь указывается один раз |
| Anki + плагин **AnkiConnect** (`http://127.0.0.1:8765`) | чтение карточек и запись звука | Anki должен быть запущен |
| Папка с весами голосов | кто говорит | `GPT_weights*` / `SoVITS_weights*` внутри движка |
| **Референс** голоса 3–10 с + текст промпта | клонирование тембра | wav-файл, выбирается вкладкой «Голос» |
| Поля карточки | откуда брать текст, куда писать звук | дефолты: `Sentence`/`SentenceAudio`, `Expression`/`ExpressionAudio`; настраиваются |
| Любое поле с чтением слова (простое `あい` или фуригана `相欠[あいが]き`) | проверенное чтение слова | поле колоды; указывается как источник чтения (§5) |

Путь к движку резолвится по приоритету: env `GPT_SOVITS_ROOT` →
`gptsovits_path.txt` рядом с программой → `%APPDATA%\AnkiVoice\config.json`
(пишет exe) → собственная папка инструмента.

Пустые поля допустимы: нет аудио-поля — будет создано при озвучке; нет
референса — голос показывается с ✗, synth его не пустит (но пустой
референс в `selftest` — не ошибка, а предупреждение).

## 2. Как устроено (файлы и две точки входа)

| Файл | Роль |
|---|---|

| `anki_web.py` | локальный HTTP-сервер интерфейса: только 127.0.0.1, stdlib `http.server`, SSE-поток лога; собирает те же аргументы CLI, что и tkinter-окно |

| `voice_pipeline.py` | **вся логика**: AnkiConnect, голоса, сервер, хирагана, подстановка чтения, синтез, запись звука |

| `voices.json` | реестр голосов: веса, референс, промпт, sampling-параметры. Относительные пути считаются от папки движка |

| `sudachi_g2p.py` | помощник-«читатель» иероглифов: SudachiPy 0.7 (движок sudachi.rs) + словарь UniDic 20261015; работает в СВОЁМ Python (см. §4) |
| `pyruntime.zip` | встраиваемый Python 3.13 + SudachiPy 0.7.0 (~14 МБ); разворачивается в `pyruntime\` при первом запуске |
| `sudachidict.zip` | словарь Sudachi core 20261015 (~73 МБ; сам system.dic 193 МБ не влезает в GitHub); распаковывает помощник один раз |
| `anki_tts.py` | старый одноразовый скрипт, оставлен для истории, не используется |

Важное разделение: **exe запускает `voice_pipeline.py` с диска** — правки
пайплайна действуют сразу, пересборка exe нужна только для `anki_gui.py`,
`anki_web.py` и `anki_web_page.py`.

## 3. Как работает озвучка (конвейер, по шагам)

Одна карточка → два независимых аудио (предложение и слово), режимы
`sentence` / `expression` / `both` (дефолт `both`).

```
AnkiConnect notesInfo
      │
      ├─ ПРЕДЛОЖЕНИЕ ──────────────────────────────┐
      │   1. inject_reading: чтение из поля-источника │
      │      подставляется в текст (см. §5)        │
      │   2. kanaize → хирагана (см. §4)           │
      │                                            ▼
      ├─ СЛОВО: word_text (написание или чтение из поля) → kanaize
      │
      ▼
Синтез: POST http://127.0.0.1:9880/tts (api_v2.py)
      │   ogg; при ошибке — повтор wav; звук < 1 КБ = ошибка, не «успех»
      ▼
media_name = tts_<голос>_<noteId>_<поле>_<sha1(text+voice)>
      ▼
AnkiConnect storeMediaFile → updateNoteFields → [sound:...]
```

Детали поведения:

* уже озвученные карточки пропускаются (защита от повторной работы);
  `--force` / чекбокс «переозвучить всё» — переделать;
* одинаковый текст в батче синтезируется один раз (кэш по
  `текст+seed+speed`); у пакетной озвучки одна ошибка не роняет остальные;
* клонирование (`clone` / `make-deck`): копия карточки в новую колоду с
  очисткой аудио-полей и тегом голоса; `check` проверяет, что в каждом
  аудио-поле есть `[sound:...]` **и файл реально лежит в медиатеке**;
* сервер GPT-SoVITS поднимается/переключается сам: `ensure_voice` ставит
  веса через `/control`, при сбое — полный перезапуск и повтор.

### Команды (`pipeline.bat <команда>`)

| Команда | Что делает |
|---|---|
| `list` | голоса и их состояние |
| `add --name … --gpt … --sovits … --ref … --prompt-text …` | новый голос в `voices.json` |
| `scan [--apply]` | найти веса в движке, дописать голоса (идемпотентно) |
| `test --voice X --text "…"` | синтез одного текста в `test_X.ogg` |
| `serve --voice X` | поднять сервер с голосом |
| `voice --voice X --deck "…" [--mode] [--limit] [--force]` | озвучить колоду |
| `clone --voice X --query "deck:…" [--to-deck]` | склонировать карточки |
| `make-deck` | clone + voice + check одной командой |
| `check --deck "…"` | сверка аудио-полей с медиатекой |
| `selftest` | самопроверка окружения, exit 0/1 |
| `anki_gui.py` | поднять веб-интерфейс и открыть страницу |
| `anki_gui.py --no-open [--port N]` | то же без автозапуска браузера |
| `anki_gui.py --classic` | старое tkinter-окно вместо веба |
| `anki_gui.py doctor [--json]` | диагностика без интерфейса |

## 4. Текст → хирагана (почему и как)

GPT-SoVITS разбирает японский морфологом **MeCab** (в составе pyopenjtalk)
и делает это по-своему: катакану переделывает по своим словарям, редкие
узкоспециальные иероглифы читает наугад. Сырой текст отдавать нельзя.
Свой конвейер читает иероглифы **сам, современным словарём**:

* основной «читатель» — **SudachiPy 0.7.0 (движок sudachi.rs, Rust) + словарь
  UniDic core 20261015**: готовое чтение каждой морфемы из словаря,
  включая редкие термины и окуригану
  (`高輪ゲートウェイ駅` → `タカナワゲートウェイエキ`, `欠き` → `カキ`);
* запасной ход — **pyopenjtalk/MeCab**: если встроенного рантайма нет или
  слова нет в словаре Sudachi; **цифры всегда идут через MeCab** — Sudachi
  читает числа как даты (`2024` → `二月二日`), а MeCab как числа;
* хирагана на g2p не попадает — её никто не портит, цель конвейера:
  выдать API текст максимально в хирагане.

**Встроенный рантайм.** SudachiPy 0.7 требует Python ≥ 3.10, а движку
GPT-SoVITS хватает 3.9 — поэтому разбор идёт в своём интерпретаторе,
который лежит в репозитории (`pyruntime.zip`, разворачивается в `pyruntime\`
при первом запуске). Пайплайн держит помощник `sudachi_g2p.py` живым на
весь запуск: обмен — строки JSON (запрос → токены `[поверхность,
нормализация, чтение]`), словарь загружается один раз (старт 0.22 с,
~0.5 мс на слово). При смерти помощника — автоперезапуск и повтор запроса
(дважды), дальше читает pyopenjtalk. Если SudachiPy установлен в самом
интерпретаторе движка — используется как промежуточный запасной ход
(`sudachi_local()`). Пользователю ставить ничего не нужно — всё в
репозитории.

`kanaize(text)` — шаги строго в этом порядке:

1. **NFKC-нормализация, кусками.** ASCII не трогаем (иначе `！` превратится
   в `!` и GPT-SoVITS прочитает иначе); полноразмерные буквы/цифры и
   диакритика нормализуются **подряд идущим куском** — только так
   полукатакана `ｶﾞｷｮｳ` склеивается в `ガキョウ`, а не в «か + парящий знак».
   Знаки препинания (`？！…・～`) сохраняются как есть.
2. **Латиница → катакана по буквам** (`IEC` → `アイイーシー`) для остатков.
3. **Катакана → хирагана**, с особыми случаями: ヷ ヸ ヹ ヺ (уточнённые
   «ва/ви/ву/ве»), контекстное раскрытие знаков повторения ヽ ヾ ゝ ゞ
   (повтор предыдущего слога, ゾ/ゞ — с озвончением), и исключением
   `_KEEP_KATA` — `コンニチハ`/`コンバンハ` остаются катаканой, иначе
   MeCab читает `こんにちは` частицей и даёт «こんにち**わ**».
5. **g2p (Sudachi, запасной ход pyopenjtalk)** — только если в тексте ещё
   остались иероглифы. Sudachi токенизирует текст целиком и выдаёт чтение
   каждой морфемы из словаря; слова вне словаря и цифры идут через MeCab
   (он чувствителен к контексту, нарезка ломает частицы вроде は).
6. **Повторный проход катакана → хирагана** — результат g2p местами снова
   катакана. На выходе в API уходит текст в хирагане.

**Что конвейер не трогает:** саму заметку в Anki (обрабатывается только
копия текста). Фуригана и `ExpressionReading` используются только когда
поле с ними явно указано источником чтения (§5).

Безвредная особенность: MeCab записывает долгие гласные нотацией `ー`
(`東京` → `トーキョー`, `学生` → `ガクセー`) — произношение то же, это не баг.

## 5. Подстановка чтения из карточки (ключевая фича)

Даже с современным словарём Sudachi отдельные редкие термины читаются
неверно, а **карточка уже содержит проверенное чтение**. API GPT-SoVITS
принимает только текст (канала «готовое чтение» нет), поэтому чтение
подставляется прямо в текст: движок видит хирагану — и ошибиться не может.

**Источник (настройка, CLI `--reading` / GUI «Чтение слова ← источник») —
только два режима, «авто» больше нет:**

* `"off"` (по умолчанию) — подстановки нет: предложение читает Sudachi
  само, слово озвучивается по написанию без фуриганы;
* имя поля (например `ExpressionFurigana` или `Кана`) — строго из него:
  поле содержит простое чтение (`あい`) **или фуриганную разметку**
  (`相欠[あいが]き`, разбирается автоматически); в предложение подставляется
  только если поле заполнено и разбор удался, озвучка слова — чтение из
  поля, при пустом поле — как при off (авто-подхвата нет).
  Реализация: `expression_inject_pair(note, reading_field=...)`,
  `inject_reading(..., reading=...)`, `word_text(..., reading=...)`,
  ключ `fields["reading"]` (DEFAULT_FIELDS = `"off"`).

**Разбор фуриганы** (`furiga_pair`, `«相欠[あいが]き継[つ]ぎ» → слово
`相欠き継ぎ`, чтение `あいがきつぎ`):

* пары «основа → чтение» идут по скобкам, хвост после последней скобки без
  чтения остаётся как есть;
* чтение покрывает основу, **кроме кана-окуриганы** (ки в `き継[つ]` — своя,
  её оставляем: `き` + `つ`);
* **латиницу в основе не оставляем** — её звучание уже есть в начале
  чтения, иначе задвоение (`IEC規格[アイイーシーきаку]` → `アイイーシーきаку`,
  а не `IEC` + `アイイーシー…`).

**Правила безопасности** — подстановка пропускается (предложение остаётся
как есть), если: слово не найдено в предложении целиком; чтение пустое или
равно слову; в «чтении» остались иероглифы; разметка фуриганы не совпала
со словом из `Expression`.

**Эффект на реальных карточках колоды «Архитектура»:**

| Слово | Без подстановки | С подстановкой |
|---|---|---|
| `I形梁` (`I形[アイがた]梁`) | あいがた**は**り | あいがた**ば**り (как в карточке) |
| `アイススケート場` (`…場[じょう]`) | あいすすけーと**ば** | あいすすけーと**じょう** |
| `相の間` (`相[あい]の間[ま]`) | あいのま**い** | あいの**ま** |
| `相欠き継ぎ` | ломало предложение | あいがきつぎ |

Слова без иероглифов (`IEC`, `IIW`) подстановки не получают — их и так
правильно читает шаг «латиница → катакана».

**Ограничение:** в команде `test` подстановки нет — там один текст без
карточки; работает только при озвучке карточек (`voice`/`make-deck`/GUI).

**Сравнение двух источников чтения (100 карточек колоды «Тест100»,
фуриганное поле `ExpressionFurigana` против Sudachi 0.7):**

* точное совпадение чтений — **68%**;
* расхождения (32%): в ~18 случаях точнее **поле** (доменные термины:
  `亜鉛鍍金` あえんめっき против あえんときん, `青石` あおいし против
  せいせき, `I形梁` あいがたばり против はり, `IAEE` по буквам);
  в ~5 случаях точнее **Sudachi** (в поле мусор или список чтений
  «あし,そく,たし»); остальное — лишние пробелы в поле (звучат одинаково)
  и спорные омографы.
* вывод: для доменных колод с фуриганой — режим «поле»; без фуриганы —
  `off` (Sudachi читает сам и редко ошибается).

## 6. Голоса

`voices.json` — 7 голосов: `kakuzu`, `kushina`, `madara`, `mishima_v2`,
`mishima_v2_v2proplus`, `mishima_yukio`, `shohayami` (у трёх mishima
референс пока не выбран — ✗).

* **Автоскан весов**: обход `GPT_weights*`/`SoVITS_weights*`; GPT-ckpt парится
  с SoVITS-pth **внутри одной версии** (v2Pro и v2ProPlus не смешиваются),
  берётся самая свежая эпоха; новые голоса дописываются, существующие не
  перезаписываются. Запуск: кнопка «Голоса в движке», тихий автоскан при
  старте GUI, `scan --apply` в консоли.
* **Sampling**: `temperature`/`top_p`/`top_k` хранятся на голос
  (дефолты 0.6/0.6/20 — из официального webui, звучит спокойнее, чем
  дефолты API 1.0/1.0/15), уходят в запрос при каждом синтезе; плюс
  `speed`/`seed`, текст и язык промпта, aux-референсы, чекбокс
  «без текста референса».

## 7. Интерфейс (`AnkiVoice.exe`)

Тёмная тема по умолчанию; переключатель в шапке (сохраняется в
`%APPDATA%\AnkiVoice\config.json`), чипы-статусы в шапке (Anki / Сервер /
голоса), тёмный лог-терминал, у каждого параметра приписка «в какую сторону
крутить». Три вкладки:

* **«Голос»** — список голосов, редактор голоса (референс + прослушивание,
  промпт, aux, слайдеры), кнопки «Прослушать тест», «Сохранить»,
  «Добавить голос», «Голоса в движке», «voices.json»;
* **«Anki»** — колода со счётчиком, поля карточки (в т.ч. кнопка
  «Подставить поля выбранной колоды»), режим, лимит, «переозвучить всё»;
* **«Финализация»** — «Начать озвучку», «Остановить», «Проверить колоду»,
  «Самопроверка», живой лог.

Без интерфейса: `AnkiVoice.exe doctor` → диагностика, exit 0/1.

## 9. Что исправлено (история багов)

| Проблема | Причина | Решение |
|---|---|---|
| `！` пропадал из текста | NFKC сводил `！`→`!`, и API читал иначе | нормализация только букв/цифр, ASCII и знаки не трогаются |
| `ｶﾞｷョᵤ` → «か + парящий знак» | посимвольный NFKC не склеивает `ｶ`+`ﾞ` | нормализация подряд идущих кусков целиком |
| ヽ/ᴌ давали кривые «け/げ» | неверный маппинг повторов | поправлены ヽ→ゝ, ヾ→ゞ; добавлены ヷヸヹヺ |
| `こんにちは` → «こんにち**わ**» | MeCab читает хирагану частьцей は | `_KEEP_KATA`: приветствия остаются катаканой |
| подстановка ломала предложение (`相欠あいがにして`) | кривой разбор `ExpressionFurigana` брал окуригану вместо основы | переписано: `furiga_pair` + правила `_base_reading` |
| чтение слова задваивало латиницу (`IEC`+`アイイーシー…`) | чтение в скобках покрывает и латиницу тоже | латиница из основы выбрасывается |
| `権現造` → «げ**н**げн」 | ошибка MeCab, закреплённая в словаре замен | исправлено на `ごんげん` (+ `アイススケート場=…じょう`, 枘/榫/粧) |
| синтез молча сохранял 0 байт | пустой ответ сервера принимался за успех | тело < 1 КБ = чёткая ошибка; если видеопамять на пределе — перезапуск сервера и повтор один раз (как при CUDA OOM) |
| OOM на длинном aux / чужом GPU | видеопамять 6 ГБ занята чужими процессами | `synth` при CUDA OOM сам перезапускает сервер (свежая память) и повторяет запрос один раз; в README — как распознать и что закрывать |
| `selftest` падал на голосе без референса | пустой ref считался ошибкой | пустой референс = предупреждение |
| локальные запросы шли через системный прокси | urllib использует прокси ОС (корпоративный VPN/PAC) | все запросы к `127.0.0.1` — через opener с пустым ProxyHandler |
| сервер упал в середине батча — остальные 100+ операций умирали впустую | OOM-перезапуск мог сам не подняться (закончилась ОЗУ), дальше — «connection refused» | `synth` поднимает упавший сервер заново (до 3 раз за прогон) и повторяет запрос |
| порт 9880 занят чужой программой | `tts_ready()` видит только «порт открыт» | проверка владельца порта (netstat+tasklist): чужой процесс НЕ убивается, выдаётся понятное имя/PID |
| `[sound:...]` внутри текстового поля читался вслух; `&amp;` попадал в API | `plain()` не знал про медиа-теги и HTML-сущности | `plain(strip_media=True)` для текстов на синтез; для проверки «озвучено ли поле» тег остаётся |
| битый `voices.json` → traceback | json.load без обработки | понятная ошибка с путём и подсказкой; запись атомарная (tmp + replace) |
| неверно указанный путь движка молча игнорировался | resolve_engine переходил к следующему кандидату | неподошедшие пути перечисляются в ошибке |
| два параллельных запуска дерутся за веса и перезапуск | защиты не было | lock-файл `logs\pipeline.lock` (второй экземпляр — ошибка) |
| `check_deck` качал каждый аудиофайл целиком только чтобы проверить существование | лёгкого API (getMediaFileInfo) у AnkiConnect нет | `--fast` (только поля) + `notesInfo` чанками по 400 |
| режим «Авто» был источником чтения по умолчанию | приоритеты SentenceFurigana→ExpressionFurigana скрывали реальный источник; «авто» неочевиден и ненадёжен | убран: только `"off"` (по умолчанию) и «имя поля»; поле понимает и простое чтение, и фуриганную разметку (можно указать готовое `ExpressionFurigana`) |
| редкие иероглифы читал старый словарь MeCab | Open JTalk — словарь постарее, узкие термины наугад | подключён **SudachiPy + UniDic** (чтение из словаря: `高輪ゲートウェイ駅` → `タカナワゲートウェイエキ`); запасной ход — pyopenjtalk; цифры всегда через MeCab (Sudachi читает числа как даты) |
| SudachiPy 0.7 требует Python ≥ 3.10, движку GPT-SoVITS хватает 3.9 — свежий словарь (формат V1, ≥ 20260723) в движок не поставить | связка «движок + свежий Sudachi» конфликтовала по версиям Python | SudachiPy 0.7.0 + словарь 20261015 встроены в репозиторий (`pyruntime.zip` + `sudachidict.zip`) и работают в своём интерпретаторе: долгоживущий помощник `sudachi_g2p.py` (JSON-строки, автоперезапуск при сбое); пользователю ставить ничего не нужно |

## 10. Известные ограничения

* референс строго 3–10 с; длинный aux → CUDA OOM (видеопамять всего 6 ГБ —
  чужие процессы на GPU мешают синтезу);
* подстановка включается только явным указанием поля-источника — ничего
  «автоматически сверх словаря» не делается;
* чтение в `test`-режиме идёт только через словарь (карточки нет);
* антивирус/Defender может ругаться на PyInstaller-сборку — добавить в
  исключения или пересобрать;
* `.venv/`, `видео/`, `голоса/` в папке проекта — прежний чужой проект,
  инструментом не используется.
